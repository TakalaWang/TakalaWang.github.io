最近讀完 Jocelin 寫的 [〈我去了一趟世界最大的 AI 工程年會 AI Engineer World's Fair 2026〉](https://doc.jocelinho.com/public/aiewf-2026/)，有一個觀點一直留在我腦中：在 AI 時代，**understanding 不是可有可無的附加價值，而是人能不能繼續參與下一輪開發的前提。**

這剛好也替我這半年的 AI coding 經驗，找到一個很貼切的註腳。

## 從 Copilot 到 coding agent

半年前，我還把 AI 當成比較強的 Copilot：補完一段 code、幫忙查錯、偶爾處理那些我懶得寫的樣板。後來開始真正使用 coding agent，讓它讀 repository、拆工作、改檔案、跑測試；模型也一代一代往前走。現在回頭看，差別並不只是「它能寫更多 code」，而是我能把腦中的想法做成東西的尺度被重新標定了。

以前做一支爬蟲，可能就是一個週末的 side project；一個看起來很完整的系統，則像是要好幾個人花上一學期才碰得起的東西。現在很多過去覺得太大的餅，至少已經可以快速做出第一個能跑、能被討論的版本。

我最近在做的 Online Judge 專案就是這樣。它準備進 alpha 測試，但從寒假一路做到暑假，也整整花了半年。若只看進度，確實很慢；但我慢慢發現，這半年不只是在把功能疊起來。

我也在學著理解：資料怎麼流、服務怎麼切、infra 為什麼要這樣設計、一個功能放進既有系統後會改變什麼。以前我可能只會問「這段 code 能不能寫出來」，現在更常需要問「這個系統為什麼要長成這樣，以及下一步還能怎麼變」。

## Review 的目的，不只是找 AI 有沒有犯錯

Jocelin 的文章提到，AI 生產 code 的速度已經可能超過人類逐行 review 的速度。這不代表 review 不重要，反而讓我重新想它到底該做什麼。

我越來越認同：review 的目標不該只是確認 AI 有沒有寫錯。正確性當然還是底線，該有的測試、驗證與 guardrail 一樣不能省；但人真正需要保留的注意力，是理解這次改動的意圖、架構與取捨。

因為只有理解，我們才不會在下一次需求改變時突然失去方向。只有理解，我們才提得出新的 idea，知道哪個地方可以改、哪個決定會牽動整個系統，也知道 AI 的答案到底是在幫忙，還是在把問題藏起來。

不然，人很容易從駕駛變成乘客：AI 每次送出一個 PR，我們就按一次同意。短期看起來很有效率，但久了之後，我們只剩下「它看起來可以」的判斷，卻再也說不清這個專案是怎麼運作的。那不是工具幫我變強，而是我把思考外包了。

## AI 不是只幫我把事情做完

我以前會覺得，自己對大型專案和系統架構的理解還很淺。這點到現在也沒有突然消失；但 AI 讓我有機會真的走進那些以前不敢碰的問題裡。

不是因為它替我把所有答案都做完，而是因為它把「做出一個可觀察、可修改的版本」的成本降得很低。我可以把原本只是畫在腦中的餅先做出來，再從實際的 code、部署、錯誤與使用流程中學習。遇到不懂的地方，就回去補系統、網路、資料庫或 domain knowledge；理解不足的地方，反而變得更清楚了。

所以 AI coding 對我來說不只是開發工具，也是一種學習工具。它放大了我能接觸的問題範圍，但沒有替我取消學習的責任。

這也是我加入 GVO、接觸更多專案之後最明顯的感受。除了完成公司的工作，我也開始更有能力把自己想做的產品推到能用的程度；而每一次把東西做出來，又逼著我去理解更多系統層面的細節。這是一個很快樂的循環。

## 我不想只做一個一直按同意的人

我其實很好奇：如果這半年每一次 AI 提出方案，我都只是不斷按下同意，今天的我會變成什麼樣子？

也許產品還是會被做出來，甚至短期看起來更快；但我很可能還停在半年前那個只會解局部題目、面對大型專案卻不知道從哪裡開始的人。當下一次需求變得更複雜，或者 AI 的答案彼此衝突時，我沒有足夠的理解去判斷，也沒有能力帶著它往新的方向走。

這正是我不想失去的東西。AI 可以加速實作，但我希望自己同步變得更能理解問題、更能提出問題，也更能判斷一個系統該往哪裡去。

## 工程師不會只因為 AI 會寫 code 而被淘汰

我不覺得工程師會因為 AI 很會寫 code 就消失。寫 code 當然仍是一項重要技能，但它從來不該是工程師唯一的技能。

當實作速度被大幅加快，真正稀缺的能力會更靠近：理解系統、理解需求背後的 domain、定義問題、做出取捨、驗證結果，以及把新的想法帶進下一輪迭代。AI 幫我們壓縮了「把想法翻成 code」的時間；人則更需要把時間用在「到底該做什麼、為什麼要這樣做、做完之後要往哪裡走」。

我很佩服那些效率很高的工程師，不是因為他們打字比別人快，而是因為他們清楚每一層架構各自的責任、知道什麼決定需要先做、也知道怎麼讓工具替自己放大能力。這才是我想慢慢靠近的狀態。

## 給研究所最後一年的期許

我希望自己能在研究所剩下的一年裡，繼續補強對 Computer Science、系統架構與不同 domain 的理解。

希望下一次我想做一個看起來很大的專案時，不只是因為 AI 讓我有能力把它做出來；而是我能更清楚地說出它的架構、知道它為什麼這樣設計、看得見它接下來可能會遇到什麼問題，並且熟練地使用 AI 去把這些想法落地。

AI 正在不斷變強。我希望我不是把方向盤交出去，而是在它加速的同時，也讓自己持續學習、持續理解，繼續坐在駕駛座上。
